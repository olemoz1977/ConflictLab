# 2Pair — V2 First Collision Validation Sprint v0.1

**Date:** 2026-08-29  
**Status:** FUTURE RESEARCH DESIGN DRAFT / NO PARTICIPANT ACTIVATION  
**Scope:** desk/design validation plan for the first three Decision Driver collisions.  
**Non-impact boundary:** does not modify `2pair-integrated-v0.1`, does not activate RESEARCH mode, does not authorize new participant collection, and does not create participant-facing V2 scores.

---

## 0. Sprint objective

Test whether the new Decision Driver approach is methodologically viable **before** expanding to all eight candidate drivers.

The sprint asks one narrow question:

> Can three meaningful driver collisions be represented by multiple independent visual scenes strongly enough that participant choice can later support a bounded statement about what motive won the trade-off?

The three collisions are:

```text
C-A  Autonomy ↔ Certainty
C-B  Certainty ↔ Exploration
C-C  Opportunity ↔ Protection
```

Why these three:

1. the current asset bank already contains plausible seeds;
2. they are mostly non-social, reducing demographic/narrative confounds;
3. they challenge important overlaps in the proposed ontology;
4. they test three different motivational structures rather than one repeated “open vs closed” idea.

---

## 1. Sprint outputs

The sprint is complete only when it produces:

```text
1. collision definition card for C-A, C-B, C-C
2. one preserved legacy seed per collision
3. at least two additional independent scene mechanisms specified per collision
4. confound hypotheses per mechanism
5. blind semantic-review package specification
6. perceptual-control probes
7. explicit REJECT / REBUILD criteria
8. decision whether any collision is ready for a fresh-participant validation protocol
```

This sprint does **not** require generating all missing assets yet.

# PART I — COLLISION DEFINITIONS

## 2. C-A — Autonomy ↔ Certainty

### 2.1 Participant-language conflict

```text
Laisvė rinktis / keisti / konfigūruoti
        vs
Aiškumas / iš anksto žinoma struktūra / numatomumas
```

The trade-off is not:

```text
freedom = good
rules = bad
```

Both benefits must be legitimate.

### 2.2 Theoretical anchors

Primary:

- Self-Determination Theory — autonomy;
- Schwartz self-direction vs conservation/security-related priorities;
- Need for Cognitive Closure / predictability as a Certainty anchor.

Secondary/context only:

- SCARF autonomy/certainty;
- Locus of Control as an alternative explanation;
- old CR architecture as historical design material, not evidence.

### 2.3 Seed item

```text
CR-PO-01
partitioned space vs open space
```

Working hypothesis:

```text
partitioned -> clearer predefined organization
open        -> more room to configure / fewer constraints
```

Known confounds:

```text
edge density
visual load
segmentation preference
open-space aesthetics
abstract-board interpretation
```

### 2.4 Independent mechanism candidates

#### A2 — workspace configuration

Same neutral workspace/task.

Variant 1:
- movable modules / several valid arrangements;
- user can choose placement/order.

Variant 2:
- predefined docking/placement structure;
- clear locations and sequence.

Must hold constant:

```text
number of objects
amount of usable space
quality / cleanliness
color
lighting
camera
overall task feasibility
```

Target trade-off:

```text
self-directed configuration
vs
predictable pre-organization
```

#### A3 — process / route sequence

Same start and same end state.

Variant 1:
- multiple equivalent paths / order can be chosen.

Variant 2:
- one clear recommended sequence / route.

Important:

- do not make the flexible route shorter, more scenic or more rewarding;
- do not make the predefined route safer or visibly easier unless safety is explicitly part of the collision.

#### A4 — modular layout

Same set of neutral physical pieces.

Variant 1:
- placement remains open.

Variant 2:
- visible guides or slots define where items go.

This can reuse design lessons from `CR-PZ` / `CR-FS`, but those old assets should act as nuisance controls rather than direct scoring items.

### 2.5 Perceptual controls

Candidate probes:

```text
CR-PZ -> segmentation/line preference
CR-FS -> slot/pattern preference
CS-CA -> composition/reference-frame preference
3361/3362 -> geometric boundary/complexity controls
```

### 2.6 C-A falsification targets

C-A fails as a general collision if:

- responses track visual openness regardless of functional autonomy;
- “Certainty” choices are mostly described as prettier/neater;
- flexible choices are consistently driven by lower edge density;
- participant rankings do not carry across workspace, route and modular-layout mechanisms;
- external autonomy/closure measures show no theoretically coherent relation once perceptual preference is modeled.

## 3. C-B — Certainty ↔ Exploration

### 3.1 Participant-language conflict

```text
Žinoti / aiškiai matyti / sumažinti nežinomybę
        vs
Palikti erdvės atradimui / tyrinėjimui / paslapčiai
```

Not:

```text
informed = rational
gaps = irrational
```

Both must offer plausible value.

### 3.2 Theoretical anchors

Primary:

- Need for Cognitive Closure / predictability;
- Schwartz stimulation/self-direction for Exploration;
- explore–exploit literature as a validation/task family, not an automatic person score.

Secondary:

- Predictive Processing as theoretical background only;
- Regulatory Focus where discovery implies potential gain, but this must not redefine Exploration.

### 3.3 Seed item B1 — Pair P0 open/closed box

```text
P0-003
open cardboard box vs closed cardboard box
```

Working collision:

```text
resolved visible content
vs
unresolved / discoverable content
```

Confounds:

```text
packing material visibility
completion state
reward expectation
generic curiosity
open-object affordance
```

### 3.4 Seed/rebuild item B2 — partial reveal

```text
CS-PR-01
more-reveal vs less-reveal
```

Useful historical language:

```text
“Be paslėptų detalių”
“Paslaptingumas”
```

But current pair must not be treated as scoring eligible because of salience/reveal and historical format confounds.

### 3.5 Independent mechanism candidates

#### B3 — envelope / information state

Library shell:

```text
2767.png
```

Build from a single base scene.

Variant 1:
- enough information is visible to understand the message/category without creating a positive or negative content reward.

Variant 2:
- content remains unknown but legitimate to leave unopened.

Do not use readable semantic text in the measured image.

Possible mechanism:

- neutral coded document/card where structure is visible vs contents remain covered;
- avoid emotionally loaded personal letters.

#### B4 — route definition, not object reveal

Same environment and destination value.

Variant 1:
- route/end point is defined.

Variant 2:
- route contains a genuinely optional discoverable branch.

This is important because B1/B2/B3 are all “reveal” mechanisms. B4 tests whether the collision survives a different causal mechanism.

Historical path-design controls from N0 remain applicable:

```text
same foreground
same light
same path width
no brighter clearing
no scenic reward asymmetry
```

#### B5 — outcome/configuration definition

Same task materials.

Variant 1:
- final configuration/outcome is clearly specified.

Variant 2:
- several legitimate outcomes remain discoverable.

This must be separated from Autonomy: both variants should allow equal agency over execution; only outcome definition changes.

### 3.6 Perceptual controls

```text
CS-PR current pair -> reveal/salience comparison
CS-CA -> reference-frame control
rough/smooth / geometric controls -> perceptual fluency challenge
```

### 3.7 C-B falsification targets

C-B fails if:

- “Exploration” is only generic curiosity caused by hidden objects;
- choices reverse when the same trade-off is expressed without occlusion;
- visible-content salience predicts choice better than semantic certainty/exploration reasons;
- Certainty collapses empirically into Protection;
- Exploration collapses into Opportunity/novelty with no discriminant structure.

## 4. C-C — Opportunity ↔ Protection

### 4.1 Participant-language conflict

```text
Galimybė judėti pirmyn / gauti / išbandyti
        vs
Apsauga nuo galimo praradimo / klaidos / nepageidaujamo poveikio
```

This is not a courage test.

It is not:

```text
risk taker vs coward
```

Both sides must be rational and potentially attractive.

### 4.2 Theoretical anchors

Primary:

- Regulatory Focus promotion vs prevention;
- revised Reinforcement Sensitivity Theory as reward/defensive-process background;
- Prospect/reference-dependence literature as a modifier/challenge, not necessarily a stable driver.

Secondary/context:

- Schwartz achievement/stimulation vs security;
- SCARF or threat theories only where social context is explicit.

### 4.3 Seed item C1 — Pair P0 gate

```text
P0-002
open wooden gate vs closed wooden gate
```

Working trade-off:

```text
access / continuation / possible advance
vs
boundary / containment / reduced exposure
```

Main confounds:

```text
open = more information
open = autonomy/access
closed = obstruction
closed = structure
background beyond gate may carry reward/valence
```

This is a strong conceptual seed but a difficult scoring item.

### 4.4 Independent mechanism candidates

#### C2 — threshold / elevator

Library shell:

```text
2784.png open elevator
```

Rebuild from one base scene into two matched options where:

- one option enables immediate access to a potentially beneficial next step;
- the other preserves current position / reduces exposure without looking broken or unavailable.

Current open-elevator image cannot be used directly because warm interior light makes the open state more inviting.

#### C3 — reversible vs protected action

Prefer a non-door mechanism to prevent all C-C items from becoming openness tests.

Concept example:

Same neutral task/resource.

Variant 1:
- action can produce a visible upside but commits some resource/exposure.

Variant 2:
- action preserves the resource/state but gives up the immediate upside.

Visual design must not use money, danger symbols, locks or warning colors in the first version.

#### C4 — access / reservation trade-off

Same limited neutral resource.

Variant 1:
- resource is deployed/used toward a new opportunity.

Variant 2:
- resource is held in reserve / protected for later.

This offers a structurally different mechanism from “open gate.”

### 4.5 Candidate shells

```text
2782 corridor/ajar door -> high valence risk due light
2783 revolving entrance -> neutral threshold shell
2781 key/lock -> high symbolism / demand risk
2789 gate latch -> aesthetic/history confound
```

These are inspiration, not scoring items.

### 4.6 C-C falsification targets

C-C fails if:

- choices are mainly openness/brightness preferences;
- “Protection” is read as blocked/negative rather than valuable downside reduction;
- Opportunity collapses into Exploration;
- Protection collapses into Certainty;
- the gate mechanism produces a pattern that disappears in resource/action mechanisms.

# PART II — VALIDATION HARNESS

## 5. Stage 0 — blind asset packaging

Before semantic review, prepare opaque IDs.

Bad:

```text
AUT-CER-open.png
PROTECTION-gate.png
exploration-box.png
```

Required:

```text
X7Q2-A
X7Q2-B
M4K8-A
M4K8-B
...
```

The mapping file stays separate from the rater package.

---

## 6. Stage 1 — blind semantic elicitation

Raters see one pair at a time without driver names.

Primary prompts:

```text
1. What is the most important difference between these two options?
2. What benefit could make someone reasonably choose the left option?
3. What benefit could make someone reasonably choose the right option?
4. Does either option seem obviously better? Why?
```

Important change from the old reason-map approach:

> raters generate the language first; the project does not offer target-language categories during elicitation.

Only after collection are responses blind-coded.

---

## 7. Stage 2 — blind coding

Coder categories are defined before seeing which asset belongs to which intended collision.

Candidate top-level coding:

```text
AUTONOMY
CERTAINTY
EXPLORATION
OPPORTUNITY
PROTECTION
MASTERY
CONNECTION
INFLUENCE
AESTHETIC / PERCEPTUAL
FUNCTIONAL UTILITY
NARRATIVE / ASSOCIATION
OTHER
UNCLEAR
```

The coder may assign more than one category when the response genuinely contains multiple motives.

Do not force every response into the target pair.

Metrics to inspect later:

```text
target-benefit recovery
cross-driver contamination
perceptual/aesthetic share
left/right legitimacy
coder agreement
```

No pass threshold is frozen here.

---

## 8. Stage 3 — low-level perceptual audit

For every candidate pair collect, at minimum:

```text
luminance
contrast
edge density
whitespace
symmetry
colorfulness
salience estimate
blind aesthetic rating
blind complexity rating
```

The goal is not pixel identity.

The goal is to know whether a simpler perceptual explanation can predict later choice.

---

## 9. Stage 4 — equal-legitimacy audit

A pair cannot proceed merely because the target benefits are recognizable.

Ask independently:

```text
Could a reasonable person choose A without being foolish?
Could a reasonable person choose B without being foolish?
Does either side imply danger, damage, failure, bad taste, poverty, incompetence, isolation or another obvious negative state?
```

If one side is morally, aesthetically or functionally dominated, rebuild.

---

## 10. Stage 5 — cross-mechanism family test

The crucial V2 test is not whether one pair “works.”

For each collision compare at least three mechanisms.

Target structure:

```text
C-A AUTONOMY ↔ CERTAINTY
- spatial/configuration
- process/sequence
- workspace/modularity

C-B CERTAINTY ↔ EXPLORATION
- information reveal
- route/outcome definition
- discoverable alternatives

C-C OPPORTUNITY ↔ PROTECTION
- threshold/access
- deploy-vs-reserve resource
- upside-vs-downside action
```

If only one mechanism produces the pattern, the finding is mechanism-specific and should not become a general Driver result.

---

## 11. Stage 6 — external reference measures

Only after candidate families survive semantic/confound review.

Possible research-only battery:

```text
SDT autonomy measures
Need for Cognitive Closure
Schwartz PVQ-RR
Regulatory Focus scale
RST-PQ / RST-PQ-S
Big Five / HEXACO only for nomological/discriminant checks
```

External instruments do not define the participant-facing 2Pair result.

They test whether the proposed driver behaves in a theoretically coherent way.

# PART III — DECISION RULES

## 12. Terminal decisions per exemplar

Every exemplar ends with one of:

```text
KEEP_FOR_NEXT_STAGE
REBUILD
CONTROL_ONLY
RETIRE
```

No “maybe but use in scoring anyway.”

---

## 13. Terminal decisions per collision

Every collision ends with one of:

```text
FAMILY_CANDIDATE
MECHANISM_SPECIFIC_ONLY
MERGE_WITH_NEIGHBOR
REDEFINE
REJECT
```

Examples:

- Certainty and Protection may prove inseparable in these visual tasks -> `MERGE_WITH_NEIGHBOR` or redefine;
- Exploration may only appear under hidden-object scenes -> `MECHANISM_SPECIFIC_ONLY`;
- Autonomy may survive spatial and sequence contexts -> `FAMILY_CANDIDATE`.

---

## 14. Explicit REBUILD conditions

Rebuild an exemplar if:

```text
intended benefits are recognized but visual nuisance dominates
one side is clearly prettier / brighter / easier
position changes choice materially
semantic trade-off is valid but image quality is asymmetric
the scene accidentally adds a third major driver
```

---

## 15. Explicit RETIRE conditions

Retire if:

```text
raters cannot recover the intended competing benefits
reasons remain mostly aesthetic/object-recognition after redesign
one side cannot be made equally legitimate
the construct only appears after researcher explanation
driver interpretation depends on the same visual confound across exemplars
```

# PART IV — PRODUCT IMPLICATION

## 16. What success would unlock

If one or more collisions survive the sprint and later fresh-participant validation, 2Pair can begin producing a result of the form:

> Across several different situations, one benefit repeatedly won when it competed with another.

Example only after validation:

```text
Laisvė rinktis > Aiškumas

When more freedom to configure competed with a predefined structure,
freedom won more often across different kinds of situations.
```

The product still should not say:

```text
You are autonomous.
You dislike rules.
This is innate.
This is your personality type.
```

---

## 17. What success does NOT unlock

Success for C-A/C-B/C-C does not validate:

```text
Mastery
Connection
Influence
all eight-driver ontology
latency as motive strength
old AW/CS/CR scores
personality labels
```

Expansion is earned collision by collision.
