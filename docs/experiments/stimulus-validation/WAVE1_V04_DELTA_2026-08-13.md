# ConflictLab Human Wave 1 — v0.4 delta

**Date:** 2026-08-13
**Status:** live recruitment candidate; privacy page owner-verified; full LT/EN smoke verification still pending
**Previous verified baseline:** `wave1-v0.3`

## Purpose

Prepare Human Wave 1 for broader recruitment without changing the six stimulus pairs or their response semantics.

## Participant-facing delta from v0.3

- LT / EN interface switching
- `?lang=lt` and `?lang=en` direct language selection
- browser-language fallback when `?lang=` is absent
- short voluntary-participation/privacy notice before Start
- privacy-policy link before the session and after completion
- participant interface language captured as raw field `language` (`lt` / `en`)

## Unchanged research mechanics

- same six Wave 1 candidate pairs
- same stimulus assets
- randomized pair order
- randomized Top / Bottom asset assignment
- neutral choice prompt
- `no_clear_choice`
- optional free text
- optional reaction intensity 1–5 after image choice
- independent `hard_to_identify`
- latency begins only after both images load
- response must save successfully before progression
- `signal_mapping_status: NONE`

The methodological boundary remains:

```text
SCENE PROPERTY != PARTICIPANT RESPONSE != DERIVED SIGNAL
```

## Data delta

v0.4 adds:

```text

```

Historical v0.1–v0.3 rows remain unchanged and may have `language = NULL`.

v0.4 API writes `protocol_version = wave1-v0.4` and requires `language` to be `lt` or `en`.

## Live verification recorded

- the live privacy policy is present and opens successfully from the Wave 1 flow;

This confirmation does **not** by itself establish full v0.4 smoke-test PASS. LT and EN end-to-end data capture still need to be recorded separately.

Do not silently merge v0.3 and v0.4 sessions. Keep `protocol_version` and `language` available in analysis. Pooling across versions may be considered later only if justified, because language availability and the privacy framing are participant-facing protocol differences.
