---

## 0. Purpose

The previous Library sweep established that 2Pair already has a substantial visual concept archive. This board turns that archive into a practical V2 curation map.

The selection question is no longer:

> What psychological label can be attached to this old image?

It is:

> Can this old asset or scene be reused as one controlled realization of a predeclared driver-vs-driver collision?

The target product logic remains:

```text
controlled trade-off
-> forced choice
-> repeated independent exemplars
-> paired-comparison model
-> bounded statement about what pulled the decision
```

## 2. Curation states

Every source item gets one of five states.

```text
S1 — EXACT SEED PAIR
existing A/B pair already expresses a plausible driver conflict
but is still unvalidated for V2

S2 — REBUILD SEED
concept is promising but the current A/B realization has important confounds

S3 — SCENE SHELL
single image or concept that can seed a future matched pair

S4 — PERCEPTUAL CONTROL
useful for nuisance-preference estimation, not driver inference

S5 — ARCHIVE / REJECT FOR EARLY CORE
historical value only, or excessive demand/valence/social confounds
```

No state above means `scoring_status=true`.

## 3. Exact pair triage

### 3.1 P0-002 — open gate vs closed gate

**State:** `S1 EXACT SEED PAIR`  
**Primary V2 collision candidate:** `Opportunity ↔ Protection`  
**Secondary collision risk:** `Autonomy ↔ Protection`, `Exploration ↔ Certainty`

Why it matters:

- both sides are visually and functionally credible;
- open gate affords movement / continuation / access;
- closed gate affords containment / boundary / protection;
- the old cue language already generated competing reactions around safety, being stopped, wanting to proceed and uncertainty about what is beyond.

Main risks:

- open = more visual access / more information;
- closed = stronger boundary / structural order;
- open may be read as freedom rather than opportunity;
- closed may be read as obstruction rather than protection;
- environmental attractiveness beyond the gate can dominate.

**Decision:** preserve exact pair bytes as a historical seed and include in blind V2 semantic review. Do not assign driver score yet.

---

### 3.2 P0-003 — open box vs closed box

**State:** `S1 EXACT SEED PAIR`  
**Primary V2 collision candidate:** `Certainty ↔ Exploration`  
**Secondary risk:** `Opportunity ↔ Protection`, simple curiosity / object reveal

Why it matters:

- closed state preserves unknown information;
- open state resolves uncertainty;
- historical reaction language directly contrasted wanting to know, being able to wait, preferring not to open, clarity after opening and missing the prior mystery.

Main risks:

- open box contains visible packing material; this changes visual complexity;
- closed box may signal delivery / unopened reward;
- open can imply completion of an action, not merely certainty;
- closed can create generic curiosity that is not the broader Exploration driver.

**Decision:** preserve exact pair as one V2 semantic seed, but expect redesign before scoring.

### 3.3 CR-PO-01 — partitioned space vs open space

**State:** `S1 EXACT SEED PAIR`  
**Primary V2 collision candidate:** `Autonomy ↔ Certainty/Structure`

Strongest current evidence:

```text
partitioned -> “Organized”
open        -> “Be suvaržymų”
open        -> “Laisvė, impeovizacija”
```

Why it matters:

- both variants remain plausible and neutral;
- the choice can plausibly reflect a trade-off between predefined organization and freedom to configure;
- this is closer to an explicit SDT/Schwartz trade-off than the old CR label was.

Main risks:

- partition walls increase edge density;
- open board has lower visual load;
- visual-order preference can masquerade as Certainty;
- the abstract board is far from a real decision context.

**Decision:** strongest existing Autonomy ↔ Certainty seed. Retain exact bytes and pair it with nuisance controls plus independent scene exemplars.

## 5. Historical N0 concepts under V2

The old N0 concept-refinement work contains useful methodological assets even where the old axis assignment is obsolete.

### Forest path continues vs ends at clearing

**V2 value:** scene-family discipline, not current scoring mapping.

Relevant old controls remain excellent:

```text
same path width
same foreground
same tree density
same light
same camera
no brighter/more inviting clearing
```

Possible V2 re-entry:

- Exploration ↔ Certainty, if the “continue into unknown” vs “known endpoint” benefits can be made equal;
- Opportunity ↔ Protection only if risk/benefit can be manipulated separately from openness.

### Hourglass intermediate states

**V2 value:** process-state/perceptual control, not obvious driver item.

The old 60/40 vs 40/60 design is useful for testing whether participants react to progress/completion cues, but it does not cleanly represent Mastery without additional task meaning.

Potential use:

- control for completion/progress preference;
- later Mastery validation task, but not as direct driver scoring.

### Rough vs smooth surface

**V2 value:** perceptual-control bank.

Could estimate texture/order/aesthetic nuisance preference.

### Object facing toward vs away

**V2 value:** mostly archive/high-risk.

Old work correctly identified that readable orientation creates functional or social meaning, while neutral objects often lack a meaningful front/back.

## 7. First-bank architecture

The first V2 research bank should deliberately be **narrower than the final ontology**.

### Bank A — Autonomy ↔ Certainty

Existing seed:

```text
A1 CR-PO-01 partitioned vs open space
```

Needed independent exemplars:

```text
A2 workspace/configuration scene
A3 route/sequence scene
A4 modular-layout scene
```

Useful controls:

```text
CR-PZ segmentation
CR-FS slot/pattern
CS-CA composition/reference
```

Goal:

> separate preference for self-directed configuration from simple preference for low visual load or neatness.

---

### Bank B — Certainty ↔ Exploration

Existing/rebuild seeds:

```text
B1 P0-003 open vs closed box
B2 CS-PR partial reveal — redesign
```

Library shells:

```text
B3 sealed/open envelope from one base image
B4 hidden/revealed object with matched salience
B5 unknown/defined path endpoint if visual valence can be controlled
```

Goal:

> distinguish desire for resolved information from attraction to novelty, mystery or discovery.

Important: B1/B2/B3 cannot all rely on simple “more object visible” logic and then be called independent exemplars. At least one exemplar must operationalize Certainty/Exploration through a different mechanism, e.g. known route vs optional discovery rather than occlusion.

---

### Bank C — Opportunity ↔ Protection

Existing seed:

```text
C1 P0-002 open vs closed gate
```

Library shells:

```text
C2 elevator threshold
C3 neutral doorway/entrance
C4 access mechanism / route scene
```

Goal:

> create situations where one option credibly expands possible gain/advance while the other credibly reduces downside/exposure, with neither side being the “good” answer.

Major challenge:

```text
open/closed
```

naturally also changes:

```text
information visibility
autonomy/access
perceived invitation
visual openness
```

Therefore this collision requires at least one non-threshold exemplar before it can be generalized.

## 8. Why the first bank should stop at three collisions

The current library gives enough material to test whether the **Decision Driver methodology itself** works without pretending all eight drivers already have visual operationalizations.

A first methodological proof can ask:

```text
Can one collision be represented by multiple independent scenes?
Do blind reasons recover the intended competing benefits?
Do item effects dominate participant effects?
Can perceptual controls explain away the apparent driver signal?
Does the same person show a coherent ranking across the three collisions?
```

If the answer is no, there is no reason to generate Mastery/Connection/Influence families yet.

If the answer is yes, the harder social/achievement drivers can be added with a stronger method.

## 9. Scene diversity requirement

Multiple images are not automatically multiple independent exemplars.

Bad pseudo-diversity:

```text
box closed/open
envelope closed/open
gift closed/open
locker closed/open
```

All four may only measure the same reveal/opening affordance.

Required diversity is closer to:

```text
Certainty ↔ Exploration

exemplar 1: information reveal
exemplar 2: route/path optionality
exemplar 3: configuration with known vs discoverable alternatives
exemplar 4: outcome definition without object occlusion
```

The shared latent trade-off should survive mechanism changes.

## 10. Perceptual control strategy

The old “failed” pairs now become useful.

Candidate nuisance bank:

```text
segmentation / boundaries      -> CR-PZ
spacing / predefined slots     -> CR-FS
context frame / reference      -> CS-CA
sharpness / connector detail   -> CS-RE if a clean nuisance target is defined
rough / smooth                 -> archived N0 surface concept
geometry / recess / boundaries -> 3361 / 3362 scene shells
```

Purpose:

> estimate whether a participant simply likes visual order, whitespace, sharpness, symmetry or certain textures.

A future driver model can then test whether those nuisance preferences explain the same choices more parsimoniously than the motivational collision does.

---

## 11. Early rejection rules

Reject or demote a V2 candidate before participant scoring if any of the following dominates:

```text
one side is obviously prettier / brighter / safer / richer / newer
construct is readable as a symbol rather than experienced as a trade-off
only one interpretation is psychologically legitimate
free-text reasons mostly describe aesthetics or object identity
same low-level visual variable predicts choice across the family
position or device materially reverses the choice
candidate only “works” after the researcher explains what it is supposed to mean
```

A visually beautiful asset is not a reason to retain it.

---

## 12. What not to generate yet

Do not generate more images merely to fill the eight-driver table.

Specifically hold:

```text
Mastery ↔ Connection
Connection ↔ Influence
Autonomy ↔ Connection
Opportunity ↔ Connection
```

until the first three non-social collisions demonstrate that the V2 pipeline can recover a repeated trade-off across independent scene mechanisms.

This prevents a new round of theory-driven image production before the measurement method itself is proven useful.

## 13. Recommended next artifact

The next methodological object should be a **First Collision Validation Sprint** containing:

```text
Collision A: Autonomy ↔ Certainty
Collision B: Certainty ↔ Exploration
Collision C: Opportunity ↔ Protection

for each:
- exact seed item
- 2–3 proposed independent mechanisms
- known confounds
- blind semantic task
- perceptual-control probes
- terminal REJECT / REBUILD conditions
```

No participant-facing V2 score should be implemented before this sprint produces at least one defensible multi-exemplar collision family.

## 14. Current verdict

The Library audit changes the development order, not the scientific standard.

### What we have

```text
3 useful collision seeds
several strong scene shells
an unexpectedly useful perceptual-control bank
old minimal-change/confound design rules worth preserving
```

### What we do not have

```text
validated V2 driver items
balanced coverage of all eight drivers
an adaptive test bank
an individual scoring model ready for production
```

### Best next move

Do not create a full eight-driver test.

First prove that these three collisions can survive independent exemplars and confound challenge:

```text
Autonomy ↔ Certainty
Certainty ↔ Exploration
Opportunity ↔ Protection
```

If they survive, they become the first real 2Pair Decision Driver measurement core. If they fail, redesign the constructs or the visual method before expanding the ontology.
