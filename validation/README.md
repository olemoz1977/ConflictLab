# ConflictLab v0.4 — Validation Phase

## Purpose

Validation shifts focus from implementation to methodological integrity.

The question is not "does the code run?" but:
"Does the reflection serve the person without overreaching?"

## Targets

- 50 scenarios (Lithuanian, real-life contexts)
- Human feedback collection
- Resonance analysis (did the reflection feel accurate?)
- Disagreement tracking (where did the person reject the reflection?)
- Model assumption gap discovery (which theories failed silently?)

## Disagreement as Signal

A person disagreeing with a reflection is NOT a failure.
It is the most valuable feedback the system can receive.

All disagreements are logged and used to improve ModelRegistry entries.

## Scenario Structure

Each scenario file must include:
- situation description (Lithuanian)
- expected signal orientations
- applicable frameworks
- expected uncertainty profile
- sample ReflectionContract output
- space for human feedback
- space for disagreement notes
